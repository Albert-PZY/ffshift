## Why

需求方反馈"现在的暗色调太深了"，要一套偏灰的浅黑，像 IDEA 那种：底色是中性深灰而不是近黑，文字不用纯白，长时间看不累。

顺带查出两件事必须一起处理：

1. **`dark:` 变体跟的不是应用主题。** 输入框底色写的是 `bg-background dark:bg-input/32`，而 Tailwind 的 `dark:` 默认走 `@media (prefers-color-scheme: dark)` —— 跟的是**系统**配色。系统是暗色的机器上选"亮色"主题，输入框会拿到暗色的底。三套主题各写一遍变体只会更乱，所以改成语义令牌 `--field`。
2. **`FFSHIFT_SMOKE_THEME` 从 ADR-018 之后就是失效的**（主题按钮搬进设置页了，那个脚本还在按 aria-label 找标题栏按钮）。README 里标着"暗色主题"的那张图其实是亮色的。

## What Changes

- 加第三套主题 `dim`（浅黑）：底色 `oklch(0.29 0.006 285.82)`（#2B2B2E）、文字 `oklch(0.93 …)`、边框比底色亮
- 状态色相应提亮一档：底色变浅之后，暗色那套压上去不够对比（实测 info 只有 3.76:1）；新的一组在页面底与选中行底上都过 4.5:1
- 输入框/下拉/输出目录按钮的底色从 `dark:` 变体改成语义令牌 `--field`，三套主题各自定义
- 主题切换从两态变三态：亮色 / 浅黑 / 暗色（按明度排序）
- 修好自动截图的主题开关：改成走设置页（齿轮 → 外观 → 点标签 → 返回），并支持三套主题

## 影响

- 设置文件里的 `theme` 字段多了 `dim` 一个合法值；旧值 `light` / `dark` 照常
- 窗口底色多一份等价值（主进程读不到 CSS 变量）
- 不影响：字号、质量档位、输出格式、目标体积、专业参数
