## Why

"AI 参数建议"是这次交付里唯一一个**没有它产品也完整**的功能，而它带来的成本是持续的：

- 需要用户自备 API Key 才能用上真模型；没有 Key 时它退回本地关键词规则，用户输入的
  "压到 50MB 发微信" 会被三个 if 分支处理成一个档位建议——这跟界面上的三档预设是同一件事，
  多一层包装反而让人以为背后有判断；
- 它是最脆弱的一环：模型不按 JSON 输出要靠散文提取兜底（`docs/testing.md` 的失败记录里，
  模型连续两次不守格式），一次网络抖动就要降级并给用户解释"这是规则给的"；
- 主界面因此多了一整块输入区，而这个产品的承诺恰恰是"不用懂参数也能转好视频"——
  档位选「更小」比描述一句话更快。

需要判断"该压到多少"的场景，现在的做法是目标体积输入框（可留空）+ 三档预设，覆盖了同一批需求，
且行为完全确定、可测、不依赖网络。

## What Changes

- 删除应用内的 AI 参数建议：界面上的建议输入区、IPC 通道、主进程的模型调用与降级规则、
  以及 `src/lib/ai-suggest.ts` 整套解析与兜底逻辑
- 保留「目标体积」输入框：它本来就不依赖 AI 建议就能独立使用
- 界面文案与截图去掉相关入口；README 的能力清单去掉一条
- **不动开发侧自动化里的 LLM**（提交后生成文档草稿，见 `docs/automation.md`）：那是协作工具，
  不是产品功能，与本次移除无关

## 影响

- 渲染进程不再有 AI 相关的 IPC 通道，preload 白名单少一项
- `WORKBUDDY_API_KEY` 只被开发侧脚本使用，应用运行不再读任何密钥
- 设置文件结构不变（档位、输出格式、输出目录、历史、预设、主题都不受影响）
- 移除一个纯函数模块与它的一份测试；`docs/testing.md` 的用例数会下降
