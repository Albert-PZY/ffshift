## Why

代码能跑不等于能读。这个项目从第一天就把"可交接"写进选型原则（ADR-008），但代码层面的规矩一直散在提交信息与口头约定里：注释写什么、纯逻辑放哪、空值怎么表达，没有人能一眼查到。

把规矩写成规格，是为了下次改代码时不用重新做一遍判断——尤其是当接手的人是别人，或者三个月后的自己。

## What Changes

- 新增 `code-standards` 能力：注释、分层、类型、错误、依赖、命名六条要求
- 每条都配可检验的场景，而不是"要写得好"这种没法判断的表述

## 影响

- 不改任何运行时代码；这是一份写给后续改动的规范
- 已实现的代码按这份规范复核过：删掉两处死代码与随之无用的 import
