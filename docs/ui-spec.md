# FFShift 界面规格

> 这份文件描述**当前实现**的界面结构与交互契约，改动界面前先读它。
> 视觉规范（颜色、字体、间距、动效、主题）在 `docs/design-system.md`，这里只讲结构与行为。
>
> 历史：本文件原名"交给 v0.app 重构用"，2026-09-23 的界面重构（ADR-015）完成后改写为现状规格。
> 那次重构把单屏纵向布局换成了三栏工作台；同日补上亮暗两套主题（ADR-016）。功能性条款未变。

## 1. 这个产品是什么

Windows 桌面视频格式转换器。用户把视频拖进来，选一个质量档位和一个输出格式，点开始，看着进度，完成后打开输出目录。

它代替的是"打开命令行敲 ffmpeg 参数"这件事——所以界面的首要目标是**让人不用理解参数也能做出正确选择**。

## 2. 界面结构

界面分两屏，靠顶栏右上角的齿轮切换。**主界面只放"这次要转成什么"，设置页放"设置一次长期有效"的偏好**（ADR-018）。

四个分类与各自的职责：

| 分类 | 内容 | 为什么在这 |
| --- | --- | --- |
| 输出 | 默认输出目录（＋恢复默认） | 设一次能用很久 |
| 参数预设 | 预设管理 + 20 项参数分组表单 + 校验结果 | 一屏多的表单塞进对话框就得在里面再滚一遍 |
| 外观 | 主题（亮色 / 浅黑 / 暗色）、字号（10–24px） | 偏好，不是每批文件都要决定的事 |
| 关于 | 应用版本、ffmpeg 版本、硬件加速（＋重新检测） | 只读信息，不该占顶栏 |

## 3. 逐区域功能

### 标题栏（自绘）

窗口是无边框的（`electron/main.ts` 的 `frame: false`），整条 44px 都是拖拽区，可点的东西各自挂 `.no-drag`。

转换界面：

| 位置 | 内容 | 说明 |
| --- | --- | --- |
| 左 | 收起/展开设置栏按钮 | 图标互换走 `t-icon-swap` |
| 左 | **FFShift** ＋ 标语「ffmpeg 的换挡键」 | |
| 右 | 硬件状态 | 有可用编码器时 `硬件加速：nvenc / qsv / amf`，否则 `CPU 编码`；悬停解释。完整版本串在设置的「关于」里 |
| 右 | **设置**（齿轮） | `aria-label="设置"`，`data-slot="settings-button"`；点开进入设置页 |
| 右 | 最小化 / 最大化 / 关闭 | `w-12`，关闭键悬停转危险色 |

设置页：只留 `← 返回`（`data-slot="settings-back"`）与「设置」标题，右侧仍是窗口控制——标题栏是全局的，设置页也得能拖窗口、能关。

### 转换栏（左栏）

**转换设置**——三项都是每批文件都要重新决定的：

| 控件 | 说明 |
| --- | --- |
| 质量档位 | 下拉：`更清晰（存档、还要再剪辑）` / `均衡（日常使用，默认）` / `更小（发手机、省空间）` |
| 输出格式 | 下拉，选项右侧带用途说明：保持原格式 / MP4 / MKV / MOV / WebM / GIF / MP3 / M4A / Opus / FLAC / WAV |
| 目标体积 | 数字输入（MiB），留空 = 不限；越界收敛到 1–10000，不把 NaN 或负数传下去。只对这一批生效，不持久化 |

**底部动作组**（列表行形态，不是描边按钮）：

| 动作 | 说明 |
| --- | --- |
| 专业参数 | 跳到设置页的「参数预设」分类；有参数被改动时行尾标注 `N 项已自定义` |
| 添加视频 | 系统文件选择框（多选） |
| 导入文件夹 | 选文件夹，扫一层里的视频文件 |
| 清空已完成 | 移除全部已完成任务 |

### 工作区

顶部是「队列 / 历史」分段切换 + 当前视图的条数，右侧是「清空历史」（仅历史视图）与「收起详情」。

**队列行结构**：

| 位置 | 内容 |
| --- | --- |
| 左 | 缩略图 96×54；读取中显示骨架，取不到图显示 `无预览` |
| 中 | 文件名（单行截断，悬停显示完整路径） |
| 中 | 媒体信息：`时长 · 宽×高 · 体积`，例：`0:05 · 1280×720 · 4.5 MiB` |
| 中 | 转换中额外一行：进度条 ＋ `百分比 · 剩余 X · 速度`，例：`42.1% · 剩余 约 12 秒 · 1.5x` |
| 右 | 状态（固定在一列，便于按列扫读） |
| 最右 | 该状态下可用的动作，**hover / 选中 / 键盘聚焦才出现** |

**媒体信息的降级规则**（务必保留）：

- 时长读不出来 → 显示 `时长未知`（不要显示 0:00）
- 信息还没读到时 → 显示读取失败原因，或 `正在读取…`
- 进度条：百分比算不出来时（时长未知）走**不确定态**（来回滑动），文字显示 `进行中`，不假装有具体百分比
- 任何字段缺失 → 显示 `—`，**不要显示 NaN 或 undefined**

**状态与可用动作**：

| 状态值 | 文案 | 颜色语义 | 可用动作 |
| --- | --- | --- | --- |
| `reading` | 读取中 | 中性 | — |
| `ready` | 待转换 | 中性 | — |
| `queued` | 排队中 | 强调（蓝） | — |
| `running` | 转换中 | 强调（蓝） | `取消` |
| `done` | 已完成 | 成功（绿） | `移除`、详情栏里 `打开输出目录` |
| `failed` | 失败 | 危险（红） | `重试`、`移除` |
| `cancelled` | 已取消 | 警告（琥珀） | `移除` |
| `unsupported` | 不支持 | 危险（红） | `移除` |

**空态**：一句话 + 一句补充，不放插画。
`把视频拖进来` / `或者点上面的投放条选文件。支持 mp4、mov、mkv、avi、webm 等常见格式。`

**历史视图**：同一套行骨架，但没有缩略图——历史要看的是体积变化与时间；行内动作是「打开输出目录」。

### 详情栏

选中任务的完整信息：预览图、失败原因、可展开的原始日志（带「复制日志」），
「媒体信息」与「处理」两组字段（时长 / 分辨率 / 帧率 / 视频编码 / 音频编码 / 声道 / 容器 / 码率 / 像素格式 / 体积；
状态 / 体积变化 / 输出文件 / 失败次数），底部是「打开输出目录」。

### 底栏

一条，`border-t` 分成左右：

- 左：队列视图显示 `● 共 7 个 · 待转换 3 个 · 正在进行 1 个`（没有文件时 `还没有文件`）；历史视图显示 `共 N 条记录`
  —— 看历史时不再报队列的数，那两行数字属于队列，摆在历史下面会读错
- 中：`输出到源文件同目录` 或实际输出目录；**专业参数有错时换成 `专业参数有误，去设置里改完再开始`**（危险色）
- 右：**主按钮**（反白，每屏只有一个）
  - 有待转换任务：`开始转换`
  - 有任务进行中：`继续排队`
  - 没有可转换任务、或专业参数有错：禁用

### 设置页

**输出**

| 控件 | 说明 |
| --- | --- |
| 默认输出目录 | 长得像输入框，点开的是系统目录选择框；设过之后右侧出现「恢复默认」。留空则放在源文件旁边 |

**参数预设**

| 区域 | 说明 |
| --- | --- |
| 内置预设 | 7 个内置组合，点一下套用 |
| 我的预设 | 用户存的组合；点名字套用、点叉删除；最多保留上限由 `presets.ts` 决定 |
| 存为预设 | 起个名字存下当前参数；只存与默认不同的字段 |
| 导入 / 导出 | 走系统文件对话框；导入不覆盖同名预设，并告知跳过了几条 |
| 参数 | 四组（视频编码 / 画面 / 音频 / 容器与性能）；每项都有「不干预」 |

校验结果显示在参数区**顶部并吸顶**：参数表单有一屏多高，错误提示放底部等于没有。
同时主界面的「开始转换」会被禁用——错误提示在另一屏，主界面必须自己把人拦住。

**外观**：主题（亮色 / 浅黑 / 暗色，分段切换，按明度排序）与字号（10–24px 下拉，默认 14）。主题默认亮色；浅黑是偏灰的一套——底比暗色浅、文字不用纯白，长时间看没那么累。
字号调的是**根字号**：全站文字、间距、控件高度一起等比缩放，但左右两栏宽度、标题栏高度与窗口最小尺寸不变——外壳固定、只有内容缩放。
选过记住，重启首帧即正确。字号下面一行报出派生的三个字号，免得用户对着"基准 14px"猜正文到底多大。

**关于**：应用版本、ffmpeg 完整版本串（整宽、可换行）、硬件加速状态（＋「重新检测」）。

## 4. 关键交互（重构时不能丢）

1. **拖放**：整窗可投放；拖动中整窗显示虚线描边；支持一次拖入多个。只有真的离开窗口才收起提示（移到子元素上也会触发 `dragleave`）
2. **队列串行**：一次只转换一个任务，完成一个自动开始下一个
3. **读取流程**：加入列表 → `读取中` → 探测媒体信息 → 生成缩略图 → `待转换`；失败则 `不支持` 并显示原因
4. **重复导入**：同一路径已在列表里就忽略，不重复添加
5. **取消**：立即停止并清理未完成的输出文件，任务标记 `已取消`（不是失败）
6. **设置记忆**：档位、输出格式、输出目录、预设、主题、**专业参数**都会保存，下次启动恢复
7. **不覆盖源文件**：输出路径是"原名 + `.ffshift` 后缀"
8. **参数配置**：在设置页里；「不干预」永远是默认项；预设可存、可删、可导入导出；有错时禁用主界面的「开始转换」
9. **主题与字号**：主题三套（亮色 / 浅黑 / 暗色）、**默认亮色**；字号 10–24px、**默认 14**。两者都在设置的「外观」里，选过记住，启动那一刻就是对的，不会先闪一下或先小后大地跳一下
10. **两屏不混**：设置页里没有队列，转换界面里没有设置表单

## 5. 渲染需要的数据字段

界面用到的字段（重构时按这些建模 props）：

```ts
// 一个任务
interface TaskItem {
  id: string;
  path: string;              // 完整路径，悬停显示
  name: string;              // 文件名
  sizeBytes: number;
  thumbnail: string | null;  // dataURL（base64 图片）
  status: 'reading' | 'ready' | 'queued' | 'running' | 'done' | 'failed' | 'cancelled' | 'unsupported';
  info: {
    durationSec: number | null;   // null = 未知
    width: number | null;
    height: number | null;
    fps: number | null;
    videoCodec: string | null;
    audioCodec: string | null;
    channels: number | null;
    container: string | null;
    bitrateKbps: number | null;
    hasAudio: boolean;
    pixelFormat: string | null;
    hasAlpha: boolean;
  } | null;
  progress: {
    percent: number | null;       // 0–1，null = 算不出来
    remainingSec: number | null;
    outTimeSec: number | null;
    speed: number | null;         // 倍数，如 1.5
    totalSizeBytes: number | null;
  } | null;
  output: string | null;      // 完成后的产物路径
  reason: string | null;      // 不支持 / 失败的原因（人话）
  errorRaw: string | null;    // ffmpeg 原始输出尾部，供"查看原始日志"
  failCount: number;          // 连续失败次数，到 2 就不再自动入队
}
```

**格式化规则**（数字不要按原值直接显示，实现见 `src/lib/format.ts`）：

| 字段 | 规则 | 例 |
| --- | --- | --- |
| 体积 | 二进制单位，保留一位小数 | `4.5 MiB` / `512 B` |
| 时长 | 不足一小时 `分:秒`，超过 `时:分:秒` | `0:05` / `1:02:05` |
| 百分比 | 保留一位小数，越界收敛 | `42.1%` |
| 速度 | 倍数，最多两位小数、去掉多余的零 | `1.5x` / `0.85x` |
| 剩余时间 | 中文，粗略即可 | `约 12 秒` / `约 10 分` / `约 1 小时 5 分` |
| 体积变化 | 源 → 产物 + 增减百分比 | `10.8 MiB → 5.3 MiB（-51%）` |
| 任何字段缺失 | 显示 `—`，**不要显示 NaN 或 undefined** | |

## 6. 测试定位锚点

端到端测试与自动截图靠 `data-slot` 定位：

| 锚点 | 在哪 |
| --- | --- |
| `app-shell` | 外壳根节点 |
| `settings-button` / `settings-back` / `settings-view` / `settings-nav` / `settings-nav-item` / `settings-content` / `settings-section` / `settings-row` / `settings-block` | 设置页；导航项的当前分类另带 `data-active` |
| `settings-rail` / `rail-section` / `rail-actions` | 主界面左栏 |
| `task-row` / `task-status` / `task-meta` / `thumb` | 队列与历史行；状态标签另带 `data-status` |
| `param-field` / `params-errors` / `reason` / `preset-chip` / `path-button` | 参数表单、校验错误、预设芯片、输出目录按钮 |
| `status-bar` | 主界面底栏 |

**改这些属性等于改测试契约**，要同步改 `e2e/`。
主题断言看 `<html>` 上的类名（亮色不带类、浅黑是 `dim`、暗色是 `dark`），或设置页「外观」里 `data-active` 的那个标签；`theme-option` 是主题分段切换的锚点，字号看 `font-size-preview` 的派生值。
字号的可验证面：`html` 的 `font-size`、设置里的像素值、主进程窗口的 `getMinimumSize()`（应恒为 940×600）。

## 7. 已知与刻意不做

- 应用内的编码器 / CRF / 帧率等专业参数只在设置页里，主界面不暴露——主界面承诺的是"不用懂参数"
- 选择输出目录、文件夹导入、目标体积已实现；托盘通知、右键菜单集成、拖放到某个任务上仍未做
- 设置页没有搜索：四个分类加起来不到十节，加搜索框是给自己找活干
- 不打包字体文件：`Inter` 命中系统就用，否则退到系统默认无衬线
