## 1. 自动化测试（已落地）

命令：`npm run test:unit`（117 条）与 `npm run test:integration`（15 条，真实调用本机 ffmpeg）。
集成测试在环境没有 ffmpeg 时整组跳过（`describe.skipIf`），不会挡住协作者。

| 测试文件 | 覆盖点 |
| --- | --- |
| `src/lib/format.test.ts` | 字节 / 时长 / 百分比 / 速度 / 剩余时间，含非法输入与越界收敛 |
| `src/lib/progress.test.ts` | `key=value` 块解析、`out_time_ms` 实为微秒的坑、流式分块拼接 |
| `src/lib/ffmpeg-args.test.ts` | 三档预设、硬件加速、无音轨不加音频参数、目标体积反推码率、输出路径 |
| `src/lib/errors.test.ts` | 五类常见报错转人话、取消、兜底、输出打不开的误判 |
| `src/lib/ffprobe.test.ts` | 帧率换算、字段缺失、纯音频、可转换性判断（含 ffprobe 猜出来的假格式） |
| `src/lib/thumbnail-cache.test.ts` | 缓存键归一化、抽帧时间点上限 |
| `src/lib/ai-suggest.test.ts` | 白名单校验、模型不守格式时的散文提取、规则降级、提示词约束 |
| `src/lib/settings.test.ts` | 设置解析容错：坏文件、缺字段、版本不符、非法枚举值 |
| `electron/ffmpeg/probe.integration.test.ts` | 真实 ffprobe：中文空格路径、截断文件、垃圾数据、批量探测不中断 |
| `electron/ffmpeg/media.integration.test.ts` | 真实转码：抽帧与缓存命中、进度单调推进、取消并清理半成品、目标体积、损坏文件 |

另外两条端到端自检（不开界面用手点，直接跑整条链路）：

```bash
FFSHIFT_SMOKE=1 npx electron .          # 窗口能建、页面能加载
FFSHIFT_SMOKE=e2e FFSHIFT_SMOKE_FILE=<视频> FFSHIFT_SMOKE_OUTPUT=<输出> npx electron .
                                        # 渲染进程 → preload → IPC → ffmpeg 全链路
```

## 3. 测试素材（不依赖下载）

```bash
# 10 秒 720p（含音轨）
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 -f lavfi -i sine=frequency=440 \
  -t 10 -c:v libx264 -pix_fmt yuv420p -c:a aac fixture_10s.mp4

# 5 秒 4K
ffmpeg -f lavfi -i testsrc2=size=3840x2160:rate=30 -f lavfi -i sine=frequency=440 \
  -t 5 -c:v libx264 -preset ultrafast -c:a aac fixture_4k.mp4

# 5 秒无声视频
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 -t 5 -c:v libx264 -pix_fmt yuv420p fixture_noaudio.mp4
```

### 失败与返工（人工核对）

| 提交 | 环节 | 发生了什么 |
| --- | --- | --- |
| `2706be3` | 集成：垃圾数据导入 | 原本按"ffprobe 会报错"来设计，实测它把 64 KiB 的 0x09 数据猜成 cdg 容器的 cdgraphics 视频（300x216、还带 9.1 秒时长）并返回成功。改为"有没有视频轨 + 容器是否常见"双重判断，垃圾文件在导入阶段就被拦下 |
| `4b4f10a` | 集成：目标体积转换 | 两次失败：① 输出目录不存在时 ffmpeg 立刻退出（改成转换前自动建目录）② 错误翻译把"输出打不开"误判成"找不到输入文件"，会让用户白忙（调整规则顺序并补单测） |
| `4b4f10a` | 集成：取消任务 | 首轮失败原因是输出目录不存在，ffmpeg 直接退出，压根没进到取消逻辑；修目录问题后取消用例通过（cancelled + 半成品已删） |
| `a435dbb` | 端到端：AI 建议 | 模型两次不按 JSON 输出：一次长篇反问（要分辨率、时长、场景），一次直接给方案分析。定案：不指望模型守格式，改从回答里提取要点；体积优先取用户输入里的数字，避免把模型说的"微信限制 100MB"当成用户目标 |
| `9daba8f` | 单测：设置解析 | 手写设置文件（缺 `version` 字段）被过度保守地整份丢弃。改为只有版本号冲突才回默认，缺字段逐项补默认值 |
| `685b344` | 端到端（打包后的 exe） | 通过：探测 → 抽帧 → 转换 896ms，输出 2.2 MB；打包产物与开发环境行为一致 |
