# Design System · FFShift

> 构建界面前先读本文件：颜色、字体、间距、动效、组件规范都在这里，界面实现以它为准。
> 上一版（v0.app 的三栏方案 + 四层底色）由本版整体替代，取舍过程见 `docs/decisions.md` ADR-015；
> 主题从"只有暗色"到"三套（默认浅黑）"的演变见 ADR-016 / ADR-020 / ADR-021。

**来源与调整（如实标注）**

- 令牌体系、组件配方、排版尺度：内化自 [EnsoCode](https://github.com/J3n5en/EnsoCode)（MIT）的 `src/renderer/styles/globals.css` 与 `src/renderer/components/ui/`。逐条对照见下面各节。
- 风格立场（单一强调色、颜色只表达状态与唯一主按钮、禁渐变/发光/装饰插画）沿用 ADR-007，未被推翻。
- 每一处刻意的偏离都有实测依据，逐条标在下面对应位置，不混进"参考"里。

## 设计立场

高级极简 = 更少的颜色、更少的装饰、更清楚的层级。
**颜色不参与分层**：层级用 1px 边框、半透明叠加、间距与字重表达；颜色只表达状态与唯一主按钮。

EnsoCode 把这条做到了极致，本项目直接跟进：

- 窗口、侧栏、工作区、详情栏**同一种底色**（`--background`），分隔只有 1px 边框；
- 嵌套块靠 `bg-muted/20`、`bg-muted/30`、`bg-muted` 这类**半透明叠加**分出深浅；
- 浮层（对话框、下拉、提示）用 `bg-popover`，配 1px 描边与一层软阴影；
- 强调不靠第二个颜色，而是靠 `--primary` 的**反白**：亮色下是近黑底 + 白字，暗色下反过来。

这样做的收益不是"好看"，而是**界面里每一个色块都在说一件事**。反过来，一旦允许用底色分区，后面的每次改动都会多一个"这里该用哪一级底色"的问题。

## 技术底座

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 样式 | Tailwind CSS v4.3，CSS-first 配置 | 没有 `tailwind.config.js`，令牌与主题映射全在 `src/styles/globals.css` |
| 组件基座 | [Base UI](https://base-ui.com) 1.7（`@base-ui/react`） | **不是 Radix**。EnsoCode 用的是 Base UI，本项目照此对齐 |
| 变体与类名 | `class-variance-authority` + `tailwind-merge` + `clsx` | `src/lib/utils.ts` 的 `cn()`；不 merge 的话组件就失去了"可被外部覆盖"的能力 |
| 图标 | `lucide-react`，线性，1.5px 描边 | 禁止 emoji 当图标 |
| 字体 | 不打包字体文件 | `Inter` 命中系统就命中，否则退到 `system-ui`；与上游一致 |

## 主题

三套：**浅黑（默认）**、**亮色**、**暗色**。按明度从高到低排，切换入口在设置的「外观」里（ADR-018 之后顶栏没有切换按钮）。

| 项 | 做法 |
| --- | --- |
| 切换方式 | 在 `<html>` 上挂类名：亮色是根状态（不带类）、浅黑挂 `dim`、暗色挂 `dark`。切换时**先摘干净再挂**（`src/lib/theme.ts` 的 `applyTheme`），不让两个类同时在 |
| 令牌 | `:root` 亮色 + `.dim` + `.dark` 三段；命名完全一致，组件层一行都不用改 |
| 默认 | 浅黑。`DEFAULT_SETTINGS.theme = 'dim'`，旧设置文件里没有这个字段时也回落成浅黑 |
| 记忆 | 存进 `settings.json`；选过就记住 |
| 首帧不闪 | 主进程在建窗口**之前**读设置，把主题塞进渲染进程的 argv（`--ffshift-theme=`），`main.tsx` 在 `createRoot` 之前挂类名。窗口底色也用当前主题的 `--background` 等价值 |
| 组件层 | **不写 `dark:` 这类变体**。Tailwind 的 `dark:` 默认跟的是 `prefers-color-scheme`，也就是**系统**配色，不是应用里选的主题——需要随主题变的底色一律走语义令牌（如 `--field`） |

**浅黑为什么存在**：暗色的底是 `oklch(0.145)`（近黑），对比拉得比较满；浅黑把底提到 `oklch(0.29)`（中性深灰 #2B2B2E）、
前景从纯白收到 0.93，整体对比降一档，适合长时间盯着看。代价是**状态色必须重新挑**——
底色变浅之后暗色那套的 `info` 压上去只有 3.76:1，不过线。

没有"跟随系统"：跟着系统走的话，同一台机器今天亮明天暗，截图与文档对不上。要跟的话也是第四个选项。

## 全局 Token

### 颜色

命名与取值来自 EnsoCode 的 `:root`（亮）与 `.dark`（暗）两段，浅黑是本项目自己加的。**三套的同名 token 语义完全一致**，
所以组件层不用为任何一套写特例。

| Token | 亮色 | 浅黑 | 暗色 | 用途 |
| --- | --- | --- | --- | --- |
| `--background` | `oklch(1 0 0)` | `oklch(0.29 0.006 285.82)` | `oklch(0.145 0.014 285.82)` | 窗口底、侧栏、工作区、详情栏、标题栏——**所有大面板** |
| `--foreground` | `oklch(0.145 0.014 285.82)` | `oklch(0.93 0.004 285.82)` | `oklch(0.985 0 0)` | 主文字 |
| `--card` / `--popover` | 同 `--background` | 同 `--background` | 同 `--background` | 卡片与浮层。与底同色，靠描边与阴影分层 |
| `--primary` | `oklch(0.205 0.014 285.82)` | `oklch(0.96 0 0)` | `oklch(0.985 0 0)` | **反白主按钮**。全屏只有一个（"开始转换"） |
| `--primary-foreground` | `oklch(0.985 0 0)` | `oklch(0.205 0.014 285.82)` | `oklch(0.205 0.014 285.82)` | |
| `--secondary` / `--muted` / `--accent` | `oklch(0.965 0.003 285.82)` | `oklch(0.355 0.008 285.82)` | `oklch(0.269 0.014 285.82)` | 三色同值：嵌套块底、行 hover / 选中、图标按钮 hover |
| `--field` | 同 `--background` | `--input` 的 32% | `--input` 的 32% | 输入框 / 下拉触发 / 输出目录按钮的底 |
| `--muted-foreground` | `oklch(0.556 0.014 285.82)` | `oklch(0.74 0.012 285.82)` | `oklch(0.708 0.014 285.82)` | 说明、元信息（4.75 / 6.11 / 7.62） |
| `--destructive` | `oklch(0.577 0.245 27.33)` | `oklch(0.76 0.17 22.216)` | `oklch(0.704 0.191 22.216)` | 失败 / 不支持 / 破坏性操作 |
| `--success` | `oklch(0.527 0.154 150.07)` | `oklch(0.76 0.17 149.579)` | `oklch(0.723 0.192 149.579)` | 已完成 |
| `--warning` | `oklch(0.55 0.155 70.08)` ⚠️ | `oklch(0.78 0.175 70.08)` | `oklch(0.769 0.189 70.08)` | 已取消 |
| `--info` | `oklch(0.55 0.22 259.81)` ⚠️ | `oklch(0.75 0.14 259.81)` | `oklch(0.623 0.214 259.81)` | 排队中 / 转换中 / 进度条 |
| `--border` / `--input` | `oklch(0.922 0.003 285.82)` | `oklch(0.4 0.008 285.82)` | `oklch(0.269 0.014 285.82)` | 全部 1px 分隔与描边 |
| `--ring` | `oklch(0.708 0.014 285.82)` | `oklch(0.55 0.01 285.82)` | `oklch(0.439 0.014 285.82)` | 焦点环 |
| `--radius` | `0.5rem`（14px 基准下 = 7px） | 同左 | 同左 | 控件 7px / 小控件 5px / 小标签 5px，由 lg·md·sm 三档派生 |

中性色共用同一色相 `285.82`、彩度 ≤ 0.014（一个偏冷的极低彩度灰，等价于 shadcn 的 zinc）。
**色相不参与分层，层次完全来自明度**，所以界面里不会出现"暖灰混冷灰"。

**⚠️ 状态色不是照抄的，三套主题都调过。** 每个值都要在它那一套的底色与**选中行底色**上都过 4.5:1：

| | 上游值 | 上游对比度 | 本项目取值 | 本项目对比度（页面底 / 选中行底） |
| --- | --- | --- | --- | --- |
| 暗色 `--destructive` | `0.396 0.141 25.72` | 1.97:1 | `0.704 0.191 22.216` | 6.85:1 / 5.24:1 |
| 暗色 `--success` | `0.527 0.154 150.07` | 4.01:1 | `0.723 0.192 149.579` | 8.70:1 / 6.66:1 |
| 亮色 `--warning` | `0.769 0.189 70.08` | 2.15:1 | `0.55 0.155 70.08` | 4.99:1 |
| 亮色 `--info` | `0.623 0.214 259.81` | 3.76:1 | `0.55 0.22 259.81` | 5.06:1 |
| 浅黑 全部四个 | 同暗色 | 3.76–6.59:1（底色变浅之后更低） | 各提亮一档 | 5.79–7.51:1 / 4.55–5.90:1 |

原因都是同一件事：上游那两个暗色值是配白字做**实心按钮**用的，本项目当**正文色**压在面板上；
亮色那两个是从深色主题直接搬过来的，压在白底上就偏淡；浅黑则是底色变浅之后，
暗色那套压上去不够对比（`info` 只有 3.76:1）。对比度数值由 WCAG 相对亮度公式算出，不是估的。
**这是对比度不是可以照抄的部分**——改回去之前先量一遍。

状态色与状态的对应（颜色只做辅助，**文字必须同时表达**）：

| 状态 | 颜色 | Token |
| --- | --- | --- |
| 读取中 / 待转换 | 中性 | `--muted-foreground` |
| 排队中 / 转换中 | 蓝 | `--info` |
| 已完成 | 绿 | `--success` |
| 已取消 | 琥珀 | `--warning` |
| 失败 / 不支持 | 红 | `--destructive` |

对应关系写在 `src/lib/task-status.ts`（纯函数，带单测），队列行、详情栏、历史记录共用同一份——
三处各写一遍的话，加一个状态就会漏掉一处。

### 面层的用法（三条，别多）

| 面 | 用在哪 |
| --- | --- |
| `bg-background` | 所有大面板：标题栏、侧栏、工作区、详情栏、对话框底板 |
| `bg-muted` + `/20` `/70` | 嵌套块与状态：行 hover、行选中、提示卡、胶囊、快捷键块 |
| `bg-popover` | 浮层：下拉、提示气泡、对话框 |

`bg-card` 只留给"卡片式小节"（本项目实际未使用）。

**表单控件的底走 `--field` 令牌，不写 `dark:` 变体**：亮色下它就是面板白，靠 1px 边框划边界；
浅黑与暗色下才是 border 色的 32% 叠加，提亮一点点。之所以做成令牌而不是 `bg-background dark:bg-input/32`：
Tailwind 的 `dark:` 默认跟的是 `prefers-color-scheme`（系统配色），不是应用里选的主题——
系统是暗色的机器上选"亮色"，输入框会拿到暗色的底。三套主题各写一遍变体只会更乱。

**hover 用满不透明度，不打一半 alpha**。`--accent` 在亮色下是 0.965 那一档，
再乘 50% 压在白底上就等于看不见——上游在暗色下用 `bg-accent/50` 没问题，亮色下不能用。

### 字体

- 正文 `text-sm`（15px 基准下 = 13.1px）／元信息 `text-xs`（11.3px）／**小节标题** `text-label`（10.7px）／
  **机器产生的数字** `text-metric`（11.8px） + `tabular-nums`。
- `text-label` 与 `text-metric` 是 rem 令牌而不是 px：它们要跟着字号设置一起放大（ADR-019）。
  写死 px 的话，选"更大"档的人会看见正文大了、标签没大。
- 按钮与下拉在窄窗口用 15px，`sm:` 以上收到 13.1px——桌面窗口远宽于 640px，所以实际生效的是后者。
- 数字统一 `font-variant-numeric: tabular-nums`：进度、体积、码率、耗时对齐后才能扫读。
- 路径、编码名、日志用 `font-mono`（`JetBrains Mono` → `Consolas` → `ui-monospace`）。
- 小节标题固定配方：`text-label font-medium tracking-wide text-muted-foreground uppercase`。

**根字号 `--font-size-base` 是用户可调的**（设置 → 外观 → 字号，10–24px 逐像素可选，默认 14）。
也就是 **1rem = 15px、0.25rem = 3.75px** 是默认值而不是常数：`h-8` = 30px、`gap-2` = 7.5px、`px-3` = 11.25px，
字号调大这些全部等比变大。所以写尺寸时先想清楚这一处**该不该跟着缩放**：

| 该缩放（写 rem / Tailwind 数值） | 不该缩放（写死像素） |
| --- | --- |
| 文字、间距、控件高度、圆角、图标 | 两栏宽度（`264px` / `300px`）、标题栏高度 `h-[44px]`、窗口按钮 `w-[48px]`、缩略图 `h-[49px] w-24`、窗口最小尺寸 |

后者的理由分两类：标题栏与窗口按钮要和系统 chrome 对齐，缩放之后跟系统对不上；
两栏宽度与窗口下限是**外壳**——外壳要是跟着字号走，24px 下三栏骨架要占 1600px，普通笔记本装不下
（ADR-019 的第一版就是这么做的，被一次范围调整推翻了）。
所以规则是一句话：**内容随字号缩放，外壳不动**。字号很大而窗口很小时，顶栏与底栏靠文字截断降级
（文字可截断、按钮 `shrink-0`，不能让 flex 子项一路缩到 min-content 压成一列一个字）。

### 间距 / 圆角

- 间距按 3.5px 栅格走；实际高频取值：`gap-2`(7) `px-2`(7) `px-3`(10.5) `py-1.5`(5.25) `py-2`(7)。
- 面板内边距 7–10.5px（`p-2` / `p-3`）；对话框 `p-6`（21px）；列表行 `px-3 py-2`。
- 圆角三档：控件 `rounded-lg`(7px)、小控件与行 `rounded-md`(5px)、小标签 `rounded-sm`(5px)；
  对话框 `rounded-2xl`(14px)；进度槽、状态点、胶囊用 `rounded-full`。全站不混用。

### 尺寸阶梯（本项目实际值）

除标了「固定」的，其余都随字号设置等比缩放；括号里是 15px 基准（默认）下的像素值。

| 元素 | 尺寸 |
| --- | --- |
| 标题栏 | `h-[44px]`（固定），窗口按钮 `w-[48px]`（固定）× 3 |
| 左栏 / 详情栏头部、工作区头部 | `h-12`（42px） |
| 左栏宽 `264px`（固定）；详情栏宽 `300px`（固定） | 窗口默认 1200×800，最小 940×600（都不随字号变） |
| 行内图标按钮 | `h-7 w-7`（24.5px）/ `h-8 w-8`（28px）+ `rounded-md` |
| 图标尺寸 | 行内 14px（`h-3.5 w-3.5`）／主按钮与空态 16px（`h-4 w-4`）／chips 12px（`h-3 w-3`） |
| 缩略图 | `h-[3.5rem] w-24`（49 × 84，约 16:9，`rounded-md`）；详情栏里是 `aspect-video` 大图 |
| 进度条 | 槽高 1.5（5.25px）、全圆角 |
| 底栏（状态 + 主动作） | `border-t` + `px-3 py-2`，文字 `text-metric tabular-nums` |

### 动效

- 缓动统一 `cubic-bezier(0.22, 1, 0.36, 1)`（起步快、收尾稳）；浮层入场用
  `cubic-bezier(0.34, 1.56, 0.64, 1)` + `scale-95 → 1`，150ms。
- 时长只取三档：150ms（hover、浮层）/ 250ms（图标互换）/ 400–500ms（揭示）。
- 只做状态反馈，不做滚动特效、不做装饰动画。
- 从上游搬了四个真的挂在组件上的过渡：
  `t-shake-in`（校验错误抖动）、`t-shimmer`（"正在想…"流光）、
  `t-rise`（空态两行错开 40ms 落地）、`t-icon-swap`（收起/展开的图标互换）。
- `prefers-reduced-motion: reduce` 时全部关闭（`animation: none !important`）。

### 可访问性

- 正文对比度 ≥ 4.5:1（亮色实测：主文字 19.81:1、次要文字 4.75:1、状态色 4.76–5.92:1；
  暗色：18.98:1、7.62:1、5.27–9.23:1）。
- 焦点可见：`focus-visible:ring-2 ring-ring ring-offset-1 ring-offset-background`；输入框另走 3px `ring-ring/24` + `border-ring`。
- 状态不只靠颜色：每个状态都是"圆点 + 中文"，`aria-label` 带状态词。
- 纯图标按钮必须有 `aria-label` + `title`（主题切换按钮就是靠 `aria-label` 被自动截图找到的）。

## 组件规范

**主按钮（每屏仅一个）**：`bg-primary` 反白 + `rounded-lg` + `h-8`，带 `active:scale-[0.97]` 的按下反馈。
全屏只有"开始转换"用它；"添加视频""清空已完成""专业参数"一律走侧栏的列表行形态（透明底、hover 才亮），
避免一屏出现五六个看起来同等重要的入口。

**按钮变体**：`default`（反白）/ `outline`（1px 描边，hover `bg-accent`）/ `ghost` / `secondary` /
`destructive` / `destructive-outline` / `link`。尺寸 `xs` `sm` `default` `lg` `xl` + 五个纯图标尺寸。

**输入框与下拉触发**：外层容器承载边框（`rounded-lg border border-input bg-background dark:bg-input/32 shadow-xs ring-ring/24`），
内层承载尺寸与文字。触发器和输入框同款——"要填的地方"看起来应该是同一种东西。

**行**（列表、设置项）：`flex items-center gap-2 rounded-md px-2 py-2` + 左侧 `size-4` 图标槽 +
`min-w-0 flex-1 truncate` 主文本 + 右侧元信息；hover `bg-muted/70`、选中 `bg-muted`；
行内动作默认 `opacity-0`，hover / 选中 / 键盘聚焦才出现（`group-hover` / `group-data-[selected]` / `group-focus-within`）——
按钮用 `opacity` 隐身而不是 `hidden`，行宽不会因为出现按钮而跳。

**任务行**：`grid grid-cols-[auto_minmax(0,1fr)_auto_auto]`——缩略图 / 文件名 + 元信息 + 进度 / 状态 / 动作。
状态固定在最右一列，行与行之间按同一列扫读。**选中与 hover 的区别靠左侧那条 2px 的 `--info` 竖线，不靠深浅**——
亮色下两档灰色的差别小到看不出来，加一条竖线两个主题都成立。

**状态标签**：圆点 + 中文，圆点用 `bg-current` 跟文字同色，所以只有一处要维护颜色。

**进度条**：槽 `bg-input`、全圆角；指示器转换中 `bg-info`、完成 `bg-success`。
百分比算不出来时 `value` 传 `null`，走不定态（一段来回滑的色带 + 文字"进行中"），**不假装有个具体百分比**。

**空态**：一句话 + 一个动作，不放插画。`t-rise` 让标题与说明错开 40ms 落地。

**浮层的层级**：下拉与提示各自排在 `Z_INDEX.DROPDOWN` / `Z_INDEX.TOOLTIP`。
将来加对话框时注意——下拉是 portal 到 body 上的，必须排在遮罩与本体的**上面**，
否则会变成"能点开、能看见选项、就是点不中"（ADR-015 踩过一次，整屏下拉一起坏）。

**设置页**：`w-44 border-r p-2` 的分类导航（行 = `h-7 rounded-md px-2 text-xs font-medium`，
当前项 `bg-muted text-foreground`）+ 右侧内容（`mx-auto max-w-3xl p-6`，条目一栏最多 672px——
再宽眼睛要从左标签扫到右控件，扫读反而变慢）。

设置条目只用两种形状：

| 形状 | 什么时候用 | 长相 |
| --- | --- | --- |
| `SettingsRow` | 控件窄，一句话能说清 | 左标签 + 说明，右控件；行间 `border-b border-border/60` |
| `SettingsBlock` | 控件宽或是整块表单（预设列表、参数网格） | 标签与说明在上，内容占满整行 |

**吸顶的错误条**：设置页里最长的一节有一屏多高，校验结果放底部等于没有——
错误条挂在滚动区顶部（`sticky top-0`），出错时才出现。
与之配套：错误提示在设置页里，主界面的「开始转换」必须自己禁用并说明原因，
不然用户在队列那一屏看不到任何提示。

**明确不做**：渐变、发光/霓虹、第二个强调色、重阴影、装饰插画、滚动特效、emoji 图标、多个高强调按钮、用色块划分区域。

**UI 原语只留用得到的**：`src/components/ui/` 下十个原语，每一个都有真实调用点。
对话框、徽章、快捷键块、转圈这四个原语随参数面板一起删掉了——上游那五十个原语里
也有一批在它自己仓库里零引用，抄过来就是抄来一堆没人维护的代码。

## 与上游的三处刻意不同

除上面标了 ⚠️ 的颜色调整，还有三处结构性取舍：

1. **不引 framer-motion**。上游的侧栏宽度动画与分组折叠用的是 spring（`stiffness: 400, damping: 30`）。
   本项目只有"展开/收起侧栏"一处动画，用一个 CSS 宽度过渡 + `--ease-smooth-out` 就够，
   不值得为它多一个运行时依赖（ADR-008 依赖最小化）。
2. **底栏只有一条**。上游是"输入框（Composer）+ 状态行（StatsLine）"两条，因为它的主动作是发消息。
   本项目的主动作（开始转换）只作用于队列，单独占一行会空掉半行，所以合成一条：
   左边是机器给的数字，右边是唯一的主按钮。
3. **主题默认浅黑**。上游 `:root` 是亮色、`.dark` 是暗色，但它的应用跟着系统走；
   本项目是显式的两态切换，默认亮色（ADR-016）。

## 交付自检

- [ ] 只有一种实心主按钮，且每屏只有一个
- [ ] 无渐变、无发光、无装饰插画
- [ ] 层级靠 1px 边框 / 半透明叠加 / 间距 / 字重，没有靠色块堆砌
- [ ] 没有硬编码色值（`#xxxxxx`、`bg-zinc-950`、内联 `style={{ backgroundColor }}`）。
      唯一允许的例外在 `src/lib/theme.ts` 的 `windowBackground()`：主进程读不到 CSS 变量，
      那是两套 `--background` 的等价值，旁边有单测钉住。
- [ ] **两套主题都看过**：亮色与暗色各点一遍界面，hover / 选中 / 禁用态都能分辨
- [ ] 正文对比度 ≥ 4.5:1（两个主题各算一遍）；focus 可见；状态不只靠颜色
- [ ] 数字都带 `tabular-nums`
- [ ] 动效 ≤500ms 且只做状态反馈，尊重 `prefers-reduced-motion`
- [ ] 图标来自 lucide（无 emoji）；间距与圆角全局一致
- [ ] 每个可点区域有 pointer + hover + 按下态；禁用态 `opacity-64` + `pointer-events-none`
